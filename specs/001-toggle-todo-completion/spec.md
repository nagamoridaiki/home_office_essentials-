# Feature Specification: Todo の完了状態の切り替え

**Feature Branch**: `feature/issue-9-spec-kit`（git 拡張は未導入のため、機能ごとのブランチは作成していない）

**Created**: 2026-09-20

**Status**: Draft

**Input**: User description: "既存の Todo 一覧で、各項目の完了状態を切り替えられるようにする。完了状態はデータとしては存在するが、利用者には表示されず変更する手段もない。既存の一覧・追加・削除の振る舞いと応答の形は変えない。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 終わった作業を完了として記録する (Priority: P1)

利用者は Todo 一覧を見ながら作業を進める。ある項目が終わったとき、その項目を完了として記録する。
記録したあとは、一覧を見るだけでその項目が終わっていることが分かる。

**Why this priority**: 本機能の中心的な価値。「終わったこと」と「まだ終わっていないこと」を区別できるようになり、
一覧が現在の状況を表すようになる。これ単独でも利用者にとって成立した機能である。

**Independent Test**: 未完了の項目を 1 つ完了にし、一覧の表示が変わること、および画面を再読み込みしても
完了のままであることを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 未完了の項目が一覧にある、**When** 利用者がその項目を完了にする、**Then** その項目は完了として表示される
2. **Given** ある項目を完了にした直後、**When** 利用者が画面を再読み込みする、**Then** その項目は完了のまま表示される
3. **Given** 複数の項目が一覧にある、**When** 利用者が 1 つだけを完了にする、**Then** 他の項目の状態は変わらない

---

### User Story 2 - 誤って完了にした項目を戻す (Priority: P2)

利用者が誤って項目を完了にしてしまった場合、または完了にした作業をやり直す必要が生じた場合に、
その項目を未完了に戻す。

**Why this priority**: 取り消せない操作は利用者に緊張を強いる。P1 だけでも機能は成立するが、
戻せることで安心して完了操作ができるようになる。

**Independent Test**: 完了済みの項目を 1 つ未完了に戻し、一覧の表示が変わること、および再読み込み後も
未完了のままであることを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 完了の項目が一覧にある、**When** 利用者がその項目を未完了に戻す、**Then** その項目は未完了として表示される
2. **Given** ある項目を未完了に戻した直後、**When** 利用者が画面を再読み込みする、**Then** その項目は未完了のまま表示される

---

### Edge Cases

- 一覧に項目が 1 つもないとき、完了状態の操作対象が存在しないことを利用者が困らずに理解できるか
- すでに一覧から消えている項目（別の経路で削除された項目）に対して完了状態を変更しようとしたとき、
  一覧の内容が壊れないか
- 同じ項目に対して短い間隔で完了・未完了を繰り返したとき、最終的な状態が利用者の最後の操作と一致するか
- 完了状態の保存に失敗したとき、画面の表示と実際に保存されている状態が食い違ったままにならないか

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、一覧の各項目について完了か未完了かを利用者が判別できる形で示さなければならない
- **FR-002**: 利用者は、未完了の項目を完了にできなければならない
- **FR-003**: 利用者は、完了の項目を未完了に戻せなければならない
- **FR-004**: システムは、変更後の完了状態を保存し、画面の再読み込み後も同じ状態を示さなければならない
- **FR-005**: システムは、存在しない項目に対する完了状態の変更要求を失敗として扱い、一覧の内容を変えてはならない
- **FR-006**: 完了状態の変更は、その項目の表題を変えてはならない
- **FR-007**: 完了状態の変更は、一覧の並び順を変えてはならない
- **FR-008**: システムは、既存の「一覧を見る」「追加する」「削除する」の振る舞いを変えてはならない
- **FR-009**: システムは、既存の一覧・追加・削除の応答に含まれる既存の情報を、削除・改名・意味の変更をしてはならない
  （情報の追加は許容する）

### Key Entities

- **Todo**: 利用者が管理する作業項目。表題と、完了か未完了かの状態を持つ。完了状態は 2 値であり、中間の状態はない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者は、一覧上の 1 回の操作で任意の項目の完了状態を切り替えられる
- **SC-002**: 切り替えた完了状態は、画面の再読み込み後も 100% の場合で保たれる
- **SC-003**: 利用者は一覧を見ただけで、完了の項目と未完了の項目を取り違えずに判別できる
- **SC-004**: 本機能の追加前に「追加」「削除」「一覧表示」ができていた手順が、追加後も同じ手順で完了できる

## Assumptions

- 利用者は単一であり、現時点で認証や権限の概念は存在しない。したがって「誰が完了にしたか」は記録しない
- 完了状態は「完了」と「未完了」の 2 値とする。進行中などの中間状態は本機能の範囲外とする
- 完了にした項目も引き続き一覧に表示する。完了項目の非表示化や絞り込みは本機能の範囲外とする
- 完了にした日時の記録および表示は本機能の範囲外とする
- 一覧の並び順は既存のままとし、完了状態によって並べ替えない
- 既存の Todo はすべて未完了として扱われている前提で、新たな初期化作業は不要とする
