# Phase 1: データモデル

**Feature**: Todo の完了状態の切り替え | **Date**: 2026-09-20

## スキーマ変更

**なし。** 既存の `todos` テーブルをそのまま使う（research.md の決定 1）。

参考として、本機能が依存する既存の定義を再掲する。

| 列 | 型 | 本機能との関係 |
| --- | --- | --- |
| `id` | `bigint GENERATED ALWAYS AS IDENTITY` | 更新対象の指定に使う |
| `title` | `text NOT NULL` | **変更しない**（FR-006） |
| `completed` | `boolean NOT NULL DEFAULT false` | 本機能が読み書きする |
| `updated_at` | `timestamptz NOT NULL DEFAULT now()` | `todos_set_updated_at` トリガーが自動更新する |

`completed` を更新すると、既存のトリガーにより `updated_at` も自動で更新される。
アプリケーション側で `updated_at` を触る必要はない。

## エンティティ

### Todo

利用者が管理する作業項目。

| 項目 | 説明 | 制約 |
| --- | --- | --- |
| ID | リポジトリが採番する識別子 | アプリケーションからは指定できない |
| 表題（Title） | 作業の内容 | 空であってはならない（既存の `ErrEmptyTitle`） |
| 完了状態（Completed） | 完了しているかどうか | **完了 / 未完了の 2 値。中間状態は持たない** |

## 状態遷移

完了状態は次の 2 状態のみを取り、双方向に遷移できる。

```text
        完了にする
未完了  ──────────▶  完了
      ◀──────────
        未完了に戻す
```

| 遷移 | 対応する要件 | 備考 |
| --- | --- | --- |
| 未完了 → 完了 | FR-002 / US1 | 新規作成直後は必ず未完了から始まる |
| 完了 → 未完了 | FR-003 / US2 | 取り消しのための遷移 |
| 同じ状態への指定 | — | 冪等に扱う。エラーとせず、その状態のまま返す |

**この遷移はドメイン層に閉じる。** HTTP のメソッド名や SQL の語彙をドメインに持ち込まない
（constitution 原則 I）。

## 存在しない項目の扱い

指定された ID の Todo が存在しない場合、更新は失敗として扱い、一覧の内容を変えない（FR-005）。
`UPDATE ... RETURNING` は該当行がないとき 0 行を返すため、これを「見つからない」として
ドメインの誤りに変換する。

## 用語の対応

同じ概念を層ごとに別名にしない（constitution 原則 II）。

| 概念 | DB | Go | API | 画面 |
| --- | --- | --- | --- | --- |
| 完了状態 | `completed` | `Completed` | `completed` | 「完了」 |
| 識別子 | `id` | `ID` | `id` | （表示しない） |
| 表題 | `title` | `Title` | `title` | タスク名 |
