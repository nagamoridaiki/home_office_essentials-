# Backend（Go）

## 技術前提

- Go 1.27（モジュール名は `go.mod` に従う）
- HTTP は原則標準ライブラリ `net/http`
- 外部ライブラリを足す前に、標準ライブラリと既存境界で足りるか確認する

## 層と責務

クリーンアーキテクチャに沿う。パッケージ名はリポジトリの現状に合わせ、次の責務分離を守る。未整備なら追加時に内側から外側へ層を明確化する。

| 層 | 置くもの | 置かないもの |
| --- | --- | --- |
| ドメイン | エンティティ、値オブジェクト、集約、ドメインサービス、リポジトリ IF | HTTP / DB / フレームワーク |
| アプリケーション | ユースケース、入力・出力 DTO、トランザクション境界の調整 | フレームワーク固有の型、SQL |
| インフラ | リポジトリ実装、外部 API、永続化 | ビジネスルール |
| インターフェース | HTTP ハンドラ、リクエスト／レスポンス変換、CORS 等 | ドメインロジック |

- 依存は **外 → 内** のみ。循環依存を作らない
- リポジトリ IF はドメイン（またはアプリケーション）側、実装はインフラ側
- ドメインルールはドメイン層に置く。ハンドラに散らさない
- エンティティ / 値オブジェクト / 集約 / ドメインサービス / リポジトリの役割を混ぜない

## HTTP / 実装慣例

- ルーティングは Go 1.22+ のメソッド付きパターン（`METHOD /path/{id}`）と `r.PathValue`
- JSON API は適切なステータスと `Content-Type: application/json` を返す
- 開発時 CORS はフロントオリジン（通常 `http://localhost:3000`）に限定する
- 共有可変状態は排他制御する。本格永続化に移すときはインフラ層へ閉じ込める

## 変更時

- エンドポイントや契約を変えるときは、フロントの API クライアント／型とセットで整合させる
- ハンドラにビジネスルールを増やさない。ユースケースまたはドメインへ移す
