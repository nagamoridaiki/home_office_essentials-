# テスト（Go）

## どこにテストを書くか

| 層 | テスト | 確かめること |
| --- | --- | --- |
| ドメイン | 必須 | 生成時の検証、状態遷移の許可と禁止 |
| ユースケース | 必須 | 受け入れ条件（Given/When/Then）の振る舞い、エラーの伝わり方 |
| インターフェース（HTTP ハンドラ） | 任意 | リクエスト／レスポンスの変換、ステータスコード |
| インフラ（リポジトリ実装・SQL） | 不変条件に関わる場合のみ | DB 接続テスト、またはその spec の `quickstart.md` に手動の確認手順を書く |

- 状態遷移は `docs/design/02-state-transitions.md` の許可された遷移だけでなく、**禁止された遷移が拒否されること**もテストする
- 1 つの受け入れ条件に、少なくとも 1 つのテストケースを対応させる

## 書き方

- 標準の `testing` パッケージを使う。テスト用の外部ライブラリは追加しない
- 入力と期待値の組み合わせが複数あるときはテーブル駆動にし、`t.Run` のケース名は日本語で何を確かめるかを書く
- ユースケースのテストでは、リポジトリをテストファイル内の手書きのフェイク（`domain` のインターフェースを満たす構造体）に差し替える。DB に繋がない
- 公開 API 越しに確かめるため、パッケージ名は `xxx_test`（例: `usecase_test`）にする
- エラーは文字列ではなく `errors.Is` で比べる

## 実行

```bash
docker compose run --rm --no-deps api go test ./...
```

ホストに Go 1.27 があれば `backend/` で `go test ./...` でもよい。実装を終えたら、テストが通ることを確かめてから完了とする。
